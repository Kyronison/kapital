# Капитал

Браузерная многопользовательская игра о финансовой грамотности: игроки получают профессию,
вкладывают свободные деньги в активы и стараются, чтобы пассивный доход покрыл расходы.

## Структура

| Пакет | Что внутри |
| --- | --- |
| `packages/content` | Профессии, оба круга поля, колоды «Шанс», «Проект», «Новости рынка», «Соблазн», мечты и инвестиции «Свободного пути», правила |
| `packages/engine` | Движок правил: `createGame`, `applyAction`, финансовые расчёты, бот |
| `packages/protocol` | Протокол сервера и клиента: формы сообщений, типы `view`, проверка действий от клиента |
| `packages/sim` | Симуляция баланса Монте-Карло на настоящем движке |
| `packages/server` | Игровой сервер на Colyseus: аккаунты и HTTP-API под `/api`, столы по ссылке, таймер хода, боты, переподключение; база SQLite |
| `packages/web` | Браузерный клиент на React + Vite: вход, лобби со ссылкой, поле, финансовый отчёт, журнал. Графика — в `public/art` и `src/art`, см. `packages/web/ART.md` |

Движок — чистые функции без сети и базы: `applyAction(content, state, action)` возвращает новое
состояние и список событий или ошибку. Случайность идёт только из ГПСЧ, состояние которого
хранится в `GameState`, поэтому партию можно воспроизвести по seed и журналу действий.
Сервер будет вызывать тот же движок и рассылать состояние клиентам.

## Команды

```sh
pnpm install
pnpm test          # тесты правил
pnpm typecheck
pnpm sim           # таблица баланса по профессиям (2000 партий)
pnpm sim:check     # то же на 400 партиях; падает, если баланс вне коридора
pnpm sim --mode quick --games 400 --check   # то же для быстрого режима
pnpm sim:table      # партии на четверых ботов: как часто побеждает первый вышедший; --check в CI
pnpm sim:levels     # проходимость уровней «Тренировки» ботом; с --check падает вне коридора сложности
pnpm dev           # сервер и клиент вместе одной командой, Ctrl+C останавливает оба
pnpm start         # игровой сервер на http://localhost:2567 (порт — переменная PORT); то же: pnpm run server
                  # не «pnpm server»: это встроенная команда pnpm, она ничего не запустит
pnpm web           # клиент на http://localhost:5173, сервер ищет на том же хосте, порт 2567
pnpm build:web     # статическая сборка клиента в packages/web/dist
```

## Запуск на сервере

После `pnpm build:web` команда `pnpm start` раздаёт собранный сайт с того же порта, что и игру:
достаточно одного процесса и одного адреса, `http://хост:PORT`. Папку сайта можно задать
переменной `KAPITAL_WEB_DIR`. Все данные — база `kapital.sqlite` и файл `secret.key` — лежат в папке
`KAPITAL_DATA_DIR` (по умолчанию `data`): на хостинге её кладут на постоянный диск и именно её
копируют в резервную копию. Если сайт лежит на другом хостинге, при сборке укажите адрес игры:
`VITE_SERVER_URL=wss://game.example.com pnpm build:web`.

## Аккаунты

Играть можно только из аккаунта: место за столом закреплено за ним, поэтому вернуться в партию
можно с любого устройства, а незаконченные партии и прогресс «Тренировки» лежат на сервере.
Способы входа включаются переменными окружения, клиент показывает только настроенные:

| Переменные | Способ входа |
| --- | --- |
| `KAPITAL_SMTP_URL` (например `smtps://user:pass@smtp.yandex.ru:465`), `KAPITAL_MAIL_FROM` | Почта: код из письма; по желанию игрок задаёт пароль и дальше входит по нему. Без SMTP код печатается в консоль сервера (в production — только с `KAPITAL_MAIL_CONSOLE=1`) |
| `KAPITAL_GOOGLE_ID`, `KAPITAL_GOOGLE_SECRET` | Google (OAuth 2.0; redirect URI — `https://ваш-сайт/api/auth/oauth/google/callback`) |
| `KAPITAL_YANDEX_ID`, `KAPITAL_YANDEX_SECRET` | Яндекс ID (redirect URI — `https://ваш-сайт/api/auth/oauth/yandex/callback`) |
| `KAPITAL_TELEGRAM_TOKEN`, `KAPITAL_TELEGRAM_BOT` | Telegram Login Widget: токен бота и его имя; у бота в `/setdomain` указывают домен сайта |
| `KAPITAL_PUBLIC_URL` | Адрес сайта для OAuth-возврата, если сервер стоит за прокси без заголовков `X-Forwarded-*` |
| `KAPITAL_SECRET` | Ключ шифрования (32 байта в hex или base64). Если не задан, создаётся в `KAPITAL_DATA_DIR/secret.key` |

Вошедший игрок может привязать к аккаунту остальные способы (войти ещё раз другим способом) и
поменять имя или пароль в профиле на главной.

Как это хранится: пароли — scrypt, сессии — хэш токена в cookie `HttpOnly`, почта, имена входов и
сами сохранённые партии — AES-256-GCM с ключом из секрета. Запросы с изменениями принимаются только
со своего сайта (проверка `Origin`), письма с кодом и попытки ввода ограничены по частоте.
В комнату Colyseus клиент входит по одноразовому билету из `POST /api/auth/ticket`.

### В контейнере и на Fly.io

`Dockerfile` собирает сайт и запускает сервер одним процессом на порту 8080, сохранения кладёт в
`/data`. Локально: `docker build -t kapital . && docker run -p 8080:8080 -v kapital-data:/data kapital`.
Для Fly.io есть `fly.toml`: `flyctl launch --copy-config --no-deploy`, затем
`flyctl volumes create kapital_data --size 1` и `flyctl deploy`. Стол живёт в памяти одного процесса,
поэтому машина одна и не останавливается без трафика (`auto_stop_machines = "off"`).

## Протокол сервера

Клиент получает билет (`POST /api/auth/ticket`), ставит его в `client.auth.token`, создаёт стол
`client.create('kapital')` и делится ссылкой с `roomId`; остальные входят через
`client.joinById(roomId)`. Имя берётся из аккаунта; можно передать `professionId` и `dreamId`,
иначе их выберет сервер при старте.

| Сообщение клиента | Что делает |
| --- | --- |
| `add_bot` | Создатель стола добавляет бота |
| `set_turn_seconds` | Создатель стола выбирает время на ход: 30, 60, 90 секунд или 0 — без таймера |
| `start` | Создатель стола начинает партию (от 2 мест), стол закрывается для новых игроков |
| `action` | Действие движка без `playerId`, например `{ type: 'ROLL' }`: игрок определяется по соединению |

Сервер рассылает `view` (места и партия без колод и состояния ГПСЧ, плюс `turnDeadline`),
`events` (события движка с их сквозным номером: при входе — последние 200, чтобы журнал не пропадал
после перезагрузки), `chat` (при входе весь чат, затем по одному сообщению), `seat` (место и номер сохранения) и `error`
конкретному игроку. Формы всех сообщений описаны в `packages/protocol`: сервер и клиент берут типы оттуда,
а действия клиента проверяются по форме до движка (`parseClientAction`). На ход даётся 30 секунд
(или сколько выбрал создатель стола), потом его доигрывает бот. Отключившийся игрок может вернуться
в течение 60 секунд, пока за него ходит бот; позже он возвращается на своё место из аккаунта.

## Как выиграть

1. **«Круг забот».** Пассивный доход должен покрыть все расходы. Тогда в конце хода игрок
   переходит на «Свободный путь» со стартовым доходом = пассивный доход × 10.
2. **«Свободный путь».** Кредитов нет, доли инвестиций покупаются за наличные. Победа:
   накопить на свою мечту и купить её, встав на её клетку (цена — 2,4–4,8 стартового дохода),
   или вырастить доход в 4 раза. Часть инвестиций — рискованные проекты: после покупки бросают
   кубик, и при неудаче деньги пропадают, зато удачный приносит в 2–3 раза больше обычного.

`sim:check` запускается в CI и проверяет для каждой профессии: медиана ходов до выхода из
«Круга забот» 20–30, доля партий без выхода не больше 5%, медиана ходов на «Свободном пути»
от выхода до победы 10–18. `pnpm sim:table` играет партии на четверых ботов и проверяет, что
первый вышедший на «Свободный путь» выигрывает не больше 65% партий (до перебалансировки было 75%).
