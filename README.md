# Капитал

Браузерная финансовая игра: начните с профессии и ежемесячных расходов, покупайте активы, развивайте пассивный доход и накопите на мечту. Можно играть одному, с друзьями или с ботами.

![Капитал — игра о пассивном доходе](packages/web/public/og-image.jpg)

**TypeScript · React · Vite · Colyseus · SQLite**

[Быстрый запуск](#быстрый-запуск) · [Архитектура](#архитектура) · [Проверки](#проверки) · [Развёртывание](#развёртывание)

## Что реализовано

- **Партии на 1–6 участников.** Приглашение по ссылке, боты, чат, выбор времени на ход и возврат в сохранённую игру.
- **Два режима.** В классическом игрок строит доход с нуля; в быстром уже есть стартовый актив, а цели ближе.
- **Тренировка из 60 уровней.** Две части, пять ступеней сложности, отдельные цели, ограничения по ходам и оценка в звёздах.
- **28 профессий с разными стартовыми условиями.** Зарплата, расходы, обязательства и запас денег меняют выбор доступных решений.
- **Финансовые решения и события.** Сделки с активами и акциями, кредиты, вклады, рассрочки, бытовые дилеммы и последствия предыдущих решений. Среди предложений встречаются невыгодные сделки.
- **Обратная связь игроку.** Финансовый отчёт, журнал событий, статистика партий, рейтинг и прогресс тренировки в аккаунте.

## Как проходит партия

На первом поле — **«Круге забот»** — игрок получает зарплату, оплачивает расходы и собирает активы. Когда пассивный доход покрывает расходы, в конце хода открывается **«Свободный путь»**: второй круг с более крупными инвестициями и собственной мечтой.

Победить можно, купив мечту на её клетке или достигнув цели по доходу. В классическом режиме нужно увеличить стартовый доход второго круга в **5 раз**, в быстром — в **2,5 раза**. У уровней тренировки свои условия: например, создать денежный запас, покрыть часть расходов или пройти оба круга за ограниченное число ходов.

## Быстрый запуск

Нужны **Node.js 22.13+** и **pnpm 10.28.0**. В CI используется Node.js 22.

```sh
git clone https://github.com/Kyronison/kapital.git
cd kapital
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Откройте **[http://localhost:5173](http://localhost:5173)**. Команда запускает Vite и игровой сервер на порту `2567`; `Ctrl+C` останавливает оба процесса.

### Первый вход без настройки почты

Игра требует аккаунт, в том числе при локальном запуске. Если SMTP не настроен и `NODE_ENV` не равен `production`, письмо с кодом выводится в терминал сервера.

1. На странице входа отметьте согласие и укажите тестовый адрес, например `player@example.com`.
2. Нажмите «Получить код» и возьмите код из строки `[письмо]` в терминале.
3. Введите код и имя. Затем откройте «Тренировку» или создайте стол: можно начать одному либо добавить ботов.

При таком запуске письмо никуда не отправляется. Аккаунт, незаконченные партии и прогресс сохраняются локально в папке `data`. Для входа на развёрнутом сайте нужно настроить SMTP или один из поддерживаемых провайдеров; общих демонстрационных учётных данных в проекте нет.

## Архитектура

Проект организован как monorepo из шести пакетов. Один движок правил используется игровым сервером, ботами, тестами и симуляциями баланса.

| Пакет | Назначение |
| --- | --- |
| [`content`](packages/content/src) | Профессии, карточки, поля, режимы и уровни тренировки |
| [`engine`](packages/engine/src) | Чистые функции правил, финансовые расчёты, состояние партии и стратегия бота |
| [`protocol`](packages/protocol/src) | Общие типы сообщений и проверка действий клиента |
| [`server`](packages/server/src) | Комнаты Colyseus, аккаунты, таймеры, восстановление партий и SQLite |
| [`web`](packages/web/src) | Интерфейс на React: кабинет, лобби, игровое поле и финансовый отчёт |
| [`sim`](packages/sim/src) | Симуляции баланса по профессиям, режимам и уровням |

`applyAction(content, state, action)` возвращает новое состояние и события либо ошибку. Состояние генератора случайных чисел хранится в партии: одинаковые исходные данные, seed и последовательность действий дают воспроизводимый результат. Сервер применяет правила и отправляет клиентам представление без порядка колод и состояния генератора.

Подробнее: **[архитектура, протокол и настройки](docs/architecture.md)**. Оформление и состав графики: **[ART.md](packages/web/ART.md)**.

## Проверки

```sh
pnpm typecheck
pnpm test
pnpm build:web
```

Помимо тестов, в [CI](.github/workflows/ci.yml) запускаются проверки баланса на настоящем движке:

```sh
pnpm sim:check
pnpm sim --mode quick --games 400 --check
pnpm sim:table --games 400 --check
pnpm sim:table --mode quick --games 400 --check
pnpm sim:levels --games 300 --check
```

Симуляции проверяют время выхода из первого круга и завершения партии, преимущество первого вышедшего игрока за столом и проходимость уровней ботом. Для более подробного отчёта доступны `pnpm sim`, `pnpm sim:table` и `pnpm sim:levels` без `--check`.

## Развёртывание

Собранный клиент и игровой сервер могут работать одним процессом:

```sh
pnpm build:web
pnpm start
```

После сборки сайт доступен на **[http://localhost:2567](http://localhost:2567)**. Порт задаётся переменной `PORT`. Папке `KAPITAL_DATA_DIR` нужен постоянный диск: в ней находятся база и ключ шифрования.

В репозитории есть [Dockerfile](Dockerfile), [Docker Compose с Caddy](deploy/docker-compose.yml) и [конфигурация Fly.io](fly.toml). Комнаты работают в одном процессе; текущая конфигурация рассчитана на один экземпляр сервера.
